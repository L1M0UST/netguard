# CQSec 8B：NVIDIA 云端 QLoRA 训练操作手册

更新时间：2026-11-15。适用单张 NVIDIA 显卡、Ubuntu 22.04/24.04 x86-64；不适用于昇腾 NPU。

本工具包提供可执行的数据下载、初步整理、结构检查、试运行配置及 D1 开发集直测脚本。**当前没有在租用 GPU 上实际安装或训练过；正式多源数据也尚未完成。** 本手册区分环境冒烟、D1 Web 试验和后续正式多源训练。

## 1. 机器怎么租

| 组件 | 起步配置 | 用途 |
|---|---|---|
| 显卡 | 1× RTX 4090，24 GB | 8B QLoRA、2048 token 起步；4096 需实测显存 |
| 可选显卡 | 1× 48 GB 显卡，例如 RTX 6000 Ada、RTX A6000 或 A40 | 更适合 4096 及更长多事件样本；不同型号速度不同 |
| CPU 内存 | 60 GB 或以上 | 你提到的 60 GB、90 GB 均可作为首轮配置 |
| 硬盘 | 建议 150～200 GB 可持久化空间 | 原始 8B 模型约 16.4 GB，加环境、数据、多个 checkpoint 及可选合并模型 |
| 系统 | Ubuntu 22.04/24.04 x86-64，Linux glibc ≥ 2.28 | 本手册固定 Linux 依赖；不要套用到 Windows 或昇腾 |
| 连接 | SSH 或云平台终端，磁盘可下载回本地 | 本手册不依赖特定租卡平台 |

优先准备数据和操作包，再租 GPU。软件包中的 CUDA 运行时不要求安装完整 CUDA Toolkit；GPU 驱动必须与 CUDA 12.4 的 PyTorch wheel 兼容。`nvidia-smi` 显示的是驱动支持的 CUDA 版本，不等于 Python 中 PyTorch 已成功识别 GPU。

## 5. 下载并核对 8B 基座

固定基座为 [Qwen/Qwen3-8B revision b968826](https://huggingface.co/Qwen/Qwen3-8B/tree/b968826d9c46dd6066d109eabc6255188de91218)，不是旧 4B 的 GGUF；旧 4B LoRA 不能直接装入 8B。

```bash
cd ~/cqsec8b
mkdir -p models
python - <<'PY'
from huggingface_hub import snapshot_download
snapshot_download(
    repo_id='Qwen/Qwen3-8B',
    revision='b968826d9c46dd6066d109eabc6255188de91218',
    local_dir='./models/Qwen3-8B',
)
print('模型快照下载完成')
PY
```

核对模型分片和 tokenizer，不下载第二份模型：

```bash
python - <<'PY'
import json
from pathlib import Path
from transformers import AutoConfig, AutoTokenizer
p = Path('models/Qwen3-8B')
index = json.loads((p / 'model.safetensors.index.json').read_text(encoding='utf-8'))
missing = [f for f in set(index['weight_map'].values()) if not (p / f).is_file()]
assert not missing, f'缺少模型分片: {missing}'
assert AutoConfig.from_pretrained(p, local_files_only=True).model_type == 'qwen3'
tok = AutoTokenizer.from_pretrained(p, local_files_only=True)
print('分片数:', len(set(index['weight_map'].values())), '词表:', len(tok))
PY
sha256sum models/Qwen3-8B/*.safetensors > reports/base-weight-sha256.txt
```

下载失败时先解决云端到 Hugging Face 的网络访问，或从可信的已有模型目录复制并核对 revision 和全部分片；不要把其他 8B/GGUF 改名当作同一基座。

## 8. 正式 A/B/C 轮需要补齐什么

当前生成的 22,790 条只适合 D1 Web 试验；正式 A 轮应在完成 D0、D1、D2、D4 的分区与审查后重新组成。B 轮才引入 D2/D3/D4 的多事件证据、问答及报告；C 轮只使用训练诊断池的困难样本并回放前序任务。

每轮准备以下文件，放入各自的 `data/round_a`、`data/round_b`、`data/round_c`：

```text
train.jsonl       训练样本
dev.jsonl         独立场景开发样本
dataset_info.json 由下面的校验命令注册
```

每行采用 Alpaca 结构：`instruction`、`input` 和 `output` 均为字符串；其中 `input` 和 `output` 本身是 JSON 对象的字符串。`_meta` 至少有 `record_id`、`source`、`group_id`、`label_status`、`split`；同族样本必须使用同一 `group_id`，同一事件派生的问答／报告继承来源分组。`label_status` 使用 `source_label` 或 `human_reviewed`，分别表示来源标签或人工复核，并不自动保证正确。M2 输出应对齐项目的 `LLMAttackAnalysis`，阶段引用的 `evidence_event_ids` 必须来自输入事件。

本机保留封存测试文件，训练和开发数据完整后先在本机检查，例如：

```powershell
Set-Location E:\platform_taishi\taishi_platform
.venv\Scripts\python.exe training\cqsec8b\check_sft_data.py `
  --data-dir E:\platform_taishi\cqsec8b-data\formal\round_b `
  --prefix cqsec_b --test E:\platform_taishi\cqsec8b-data\sealed\round_b_test.jsonl --register
```

该命令中的 `formal`、`sealed` 文件需先实际构建，当前尚不存在。校验只检查声明分组、部分精确输入重叠、结构和事件 ID，**不能替代近重复、跨源谱系和人工标签审核**。上传时只传训练和开发数据。

当 B 数据实际准备好后，修改 `configs/round_b.yaml` 中 `adapter_name_or_path` 为 A 轮选定 checkpoint，再运行：

```bash
python check_sft_data.py --data-dir data/round_b --prefix cqsec_b --register
CUDA_VISIBLE_DEVICES=0 llamafactory-cli train configs/round_b.yaml 2>&1 | tee logs/round_b.log
```

C 轮同理，使用 `configs/round_c.yaml`、`cqsec_c` 和 B 轮选定 checkpoint。`adapter_name_or_path` 是继续训练所选适配器；这是新阶段，优化器状态重新开始。它与意外中断时从同轮完整 checkpoint 恢复优化器和步数不是同一回事。B 的 4096 token 是否适合 24 GB 显存需先做测时／显存试验。

Splunk 数据采用固定 revision `4b19e4b6824a8ba91b0f5345a3a8de488619e823`。其不少 `.log` 是 Git LFS 对象；若只看到 `version https://git-lfs.github.com/spec/v1`，读到的是指针而非日志。选择和固定需要的场景后，安装 `git-lfs`、使用稀疏检出并执行对应范围的 `git lfs pull`；按场景核对文件、标签和与 OTRF 测试集的谱系。不得把整个场景中的每条日志自动标为恶意。

## 10. 最终评测、导出和系统接入

先固定候选 checkpoint、提示词、量化方式、数据和 RAG 版本，再在封存测试上做预先约定的比较：原始 8B、8B SFT、8B SFT + 检索；当前 4B 使用匹配其旧接口的独立适配器，不能把它直接当作新 JSON 协议模型。保留每类 Precision/Recall/F1、正常误报、解析失败、unknown、事件引用和来源分组。D1 的 round4/Qwen/Claude 是攻击样本，必须分别报告，不能用它们计算正常流量 FPR。完整路线与公开 benchmark 协议见原 [训练研究方案](../../docs/research/security_log_sft_20261114/最终方案.md)。

仅当确实需要合并模型时，修改 `configs/export.yaml` 的 `adapter_name_or_path` 指向选定 checkpoint：

```bash
llamafactory-cli export configs/export.yaml
ls -lh exports/cqsec8b-merged
```

合并使用未量化 BF16 基座，不在导出配置中设置 `quantization_bit`；之后若需要 GGUF/Q4，使用与目标部署版本匹配的 llama.cpp 另行转换和量化，并比较 BF16/量化质量。导出的适配器、基座 revision、配置、数据哈希、环境和评测记录一起保存及下载。

当前 M1 的 4B 使用旧七字段与文本解析协议，M2 本地模式由编排器强制禁用模型。训练后的 8B **不会自动接入**：需要实现版本化输入、M1 标签投影、M2 本地 provider 路由、上下文和证据校验，再做影子与端到端测试。本工具包不更改正在运行的系统。
