# 赛前验证与复现说明

本文说明如何在当前项目目录中复现本次工程验收。命令默认在 `taishi_platform` 根目录运行；测试输出写入 `workspace_test/`，不会清理或覆盖演示工作区。

## 一键启动与就绪检查

1. 在 Windows 资源管理器中双击 `scripts/start_all.bat`。这是项目统一入口：启动 8001 Web/API、编排器，并在配置路径存在时启动 8008 本地模型；缺少本地模型文件时不会阻止平台启动。
2. 打开 `http://127.0.0.1:8001`。
3. 运行静态检查：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/competition_preflight.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/competition_preflight.ps1 -RequireRunningServices
```

检查只读取 `.env` 是否存在，不打印密钥。若要联网模型复核，在本机 `.env`/进程环境中配置对应变量；密钥不可放入源码、截图、报告或提交包。演示前应验证网络、配额和失败回退；纯本地验收将 M2 云端模型显式关闭。

## 运行可复现全链路验收

使用仓库内的确定性合成集（10,200 行）：

```powershell
$env:PYTHONIOENCODING = 'utf-8'
.venv\Scripts\python.exe scripts\competition_acceptance.py `
  --input tests_integration\fixtures\suite\01_main_10k.csv `
  --workspace workspace_test\competition_acceptance_demo `
  --repeat 3 `
  --output docs\evidence\competition_acceptance_demo.json
```

对项目已有的 11,000 行带标签 XLSX 执行同一流程：

```powershell
$env:PYTHONIOENCODING = 'utf-8'
.venv\Scripts\python.exe scripts\competition_acceptance.py `
  --input tests_integration\fixtures\web_alerts_full.xlsx `
  --workspace workspace_test\competition_acceptance_workbook `
  --repeat 3 `
  --output docs\evidence\competition_acceptance_workbook.json
```

每个输出文件必须使用新文件名，脚本拒绝覆盖已有证据。运行完成条件为 orchestrator `.done` 标记、M1 批次与 M2 `bundle.json` 同时存在。标签列仅在 M1/M2/bundle 全部结束后打开用于离线计分，映射计划同时记录它已被排除。JSON 包含输入 SHA-256、环境与模型元数据、重复运行时间、吞吐、逐类 precision/recall/F1、混淆矩阵、二分类误报/漏报、过滤统计，以及 M1、Bridge、M2 进程、M2 内部子阶段、Bundle 与编排器开销的分段计时。

### 指标解释

- 端到端耗时涵盖 M1、Bridge、M2、Bundle；端到端指标不等于单独模型推理耗时。
- M2 进程墙钟包含 Python/模块启动与输出写盘；`m2_internal_stages` 来自 M2 自身 `metrics.json`，是 M2 进程耗时的子集，不可与之重复相加。
- 多分类指标是基于 M1 规则/IOC/模型综合筛选结果的逐事件分类；过滤或白名单导致未产生可疑事件的行按“无告警”处理。另列二分类攻击检测指标，避免类别映射与基数差异遮蔽误报。
- 合成集和项目内带标签工作簿都是验收样本，不等于生产泛化或主办方盲测；对外引用应带上文件哈希、样本范围、运行配置及本说明中的边界。
- 重复运行可能复用本地模型回答缓存。性能报告应一并披露缓存命中情况，不能把热缓存时间说成冷启动模型延迟。

## 演示建议

先用 10,200 行合成 CSV 做速度和攻击链演示，再用 `05_attack_scenarios.pcap` 演示有限的 PCAP 元数据处理；切换到 `web_alerts_full.xlsx` 时展示 M1 真值列隔离和离线评分。至少展示正常样本、8 种带标签攻击、低/中/高等级、攻击链证据和报告导出。展示云端时仅用受控的小样本，不将 API 密钥写入演示录屏。

## 数据安全与清场

仅处理经授权的比赛样本、项目内生成夹具或经脱敏批准的日志。演示结束使用页面“重置演示”清理应用任务；性能证据目录和测试工作区需由操作者按赛事数据保留要求另行清理。不要把原始请求体、真实个人信息或密钥提交到公开仓库。

## 当前已知限制

当前竞赛验收脚本覆盖本地 M1 + 确定性 M2，未将三家云模型作为评分链路的依赖；云端模型的准确率、成本和端到端 SLA 应单独做可比盲测。历史文档中未附机器证据的预估耗时或第三方模型比较，不应当作本次实测结果引用。PCAP 支持范围见 `docs/数据来源与PCAP边界.md`。
