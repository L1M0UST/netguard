## 数据来源登记

## 标签隔离与测量

验收程序在完整流程完成后才读取真值列计算离线指标；M1 将真值字段加入排除字段，不能让它参与 schema profile、字段映射或模型输入。每份证据保留输入 SHA-256、运行环境与重复运行耗时。项目样本上的离线得分不构成独立第三方盲测；正式比赛盲测需保留原始输入哈希、规则/模型版本与评分脚本版本。

## 当前 PCAP 能力边界

当前实现是快速流元数据摘要器，不是全功能协议解码器或网络取证系统：

- 支持经典 PCAP 与 PCAPNG 中识别到的 Ethernet/IPv4 包；从 IPv4 头部解析地址、IP 协议号和 TCP/UDP 端口，按地址/协议聚合并生成 GLYPH 流摘要。
- 不重组 TCP 流，不解码 HTTP/DNS/TLS 等应用层内容，不解密 TLS，不解析 IPv6，不完整处理 IPv4 分片及所有 PCAPNG 接口/统计块语义。端口或方向等摘要不足以单独证明攻击。
- 当前分析路径仅传递提取后的流元数据/规则证据；不能对外表述为已完成 PCAP payload 的多模态语义理解。
- 默认测试用的 PCAP 由项目脚本生成，不应用真实攻击者地址/生产网络数据替代；对真实抓包应先审查授权、个人信息和敏感载荷，并执行访问控制及保留策略。

## 发布前检查

1. 为每个非合成数据文件登记原始发布方、下载日期、版本/哈希、许可、允许用途及再分发条件。
2. 将来源和标签说明与运行证据一起归档；未知来源或授权状态的文件不放进公开演示包。
3. 在 PCAP 功能演示中明确展示“IPv4 流元数据提取”，并将协议深度分析列为后续能力，不演示成 TCP 重组或内容检测。
