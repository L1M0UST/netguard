# Hugging Face 与魔搭：安全日志微调数据补充调研

调研日期：2026-11-15。本文补充[原方案](./最终方案.md)；数据集推荐是选材和试验方案，不代表已下载、已完成标注、已训练或已通过评测。

## 一、代码需求与现状

当前 M1 的本地模型对候选会话构造七字段的 HTTP 日志输入；M2 先由程序生成候选，再把事件摘要及候选技术交给模型研判，并校验模型引用的事件证据。具体见 [M1 本地研判](../../../m1/run.py#L1063)、[M2 证据构造](../../../backend/module2_chain/llm/prompt_builder.py#L99)、[M2 输出结构](../../../backend/module2_chain/llm/schemas.py)。因此，Web 载荷分类、syslog 字段理解、跨事件证据关联是三个不同训练任务，不能用通用安全问答替代。

本地可检查到的 4B 训练链使用比赛 xlsx 清洗数据及其派生、合成与回放样本；例如 [数据清洗](../../../../../code/2026年第二届重庆市AI大模型创新应用大赛/model/data/01_clean_normalize.py#L21)、[SFT 数据构造](../../../../../code/2026年第二届重庆市AI大模型创新应用大赛/model/data/02_build_sft_v1.py#L167)、[v3.2 补充](../../../../../code/2026年第二届重庆市AI大模型创新应用大赛/model/data/07_patch_v32.py#L117)。未在已检查的训练数据构造脚本中看到下列新推荐数据的显式引用；无法据此证明其他来源的文本没有相似内容，也无法证明基座预训练不包含相似内容。

当前 [8B 试验手册](../../../training/cqsec8b/操作手册.md)和 cloud pilot 包已经准备好；其中 D1 训练数据是 Web 分类试验材料，不等于已执行 8B 微调。下文新增数据没有加入该包。

## 三、补充用途与暂缓选择

- [Trendyol 防御安全指令集](https://huggingface.co/datasets/Trendyol/Trendyol-Cybersecurity-Instruction-Tuning-Dataset)，[魔搭版](https://modelscope.cn/datasets/Trendyol/Trendyol-Cybersecurity-Instruction-Tuning-Dataset)：约 53,201 条英文安全问答，Apache-2.0，适合作为检索、报告表述或少量辅助问答的候选，不是原始日志。页面预览显示只有 train，而卡片文字还列了 train/validation/test；使用前应依据实际文件核验。卡片对质量的陈述是发布方声明，仍要人工抽查。
- [hcnote 中文网络安全集](https://modelscope.cn/datasets/hcnote/Cybersecurity-High-Quality-Dataset)：魔搭 API 卡片称 270,271 条中英文问答，非专门日志集；其仓库顶部许可标记 Apache-2.0，README 却写 MIT，需先确认实际许可证及上游权利，当前暂缓作为首批主训练来源。
- [YangYang Web Attack Detection](https://huggingface.co/datasets/YangYang-Research/web-attack-detection)：625,904 条二分类文本，虽有攻击载荷，样本预览中负例混有普通英文问答句子；来源与负例真实性需进一步审计，暂不作为首批主数据或系统真实误报基准。
- [shengqin/web-attacks](https://huggingface.co/datasets/shengqin/web-attacks)：`Payload`、`Label`、`text_label`、`ID`，主要覆盖正常、SQLi、XSS；原始来源及许可证页面信息不足，暂不作为首批主数据。需与 D1、比赛集和所有测试集做跨源查重。

## 四、有没有被训练使用过

1. **别人的微调**：HF 页面将 [witfoo/witq-1.0](https://huggingface.co/witfoo/witq-1.0) 与 `syslog-to-artifact` 关联；[ThakiCloud SOC-IER-4B](https://www.thakicloud.com/tech-blog/en/owm/soc-ier-4b-open/) 说明其辅助训练使用 120 个由 Precinct6 构建的窗口。此类信息是发布者披露，不代表这些数据自动适合本系统。
2. **本项目的 4B**：已检查的可追溯数据构造脚本未显示使用这些新候选；不排除未留存过程、人工数据或文本相似性。
3. **本项目的 8B**：本地已有 D1 试验包，尚无可见的新 8B 训练运行证据。其他机器和云端是否有运行记录需要单独核对。
4. **Qwen 等基座预训练**：公开页面通常不披露可核验的逐条预训练清单，不能断言某公开数据完全未参与或一定参与。对当时尚未公开的整理版本，可以说该公开版本在发布时间前不存在，不能据此证明更早的相同原文不在预训练中。

## 五、建议的试验与评测冻结

保留原方案 D0/D1/D2/D3/D4 的职责，在正式构建前新增 syslog-to-artifact、Precinct6 的筛选试验与 Rook 样本审计。先冻结所有基准及来源，再组训练样本：

1. **Web 主任务**：D0 需按历史 4B 的实际训练来源审计；D1 按载荷族拆分并保留 Claude/Qwen/round4 原方案封存测试。历史 4B 已见过的比赛样本不能事后随机划分为它的独立测试。
2. **日志字段和解释**：syslog 先按原始事件、消息模板拆分；只对输入能支持的字段构造目标，人工审查真实、失败、正常及不确定样本。
3. **告警与关联**：AIT 按场景；WitFoo 按机构、事件、时间窗口和关联图共同分组；Rook 的所有派生记录跟随源事件所在分区。去掉 `label_binary`、`disposition`、最终关联结论、报告与答案字段等答案侧信息，仅按 M1/M2 实际可获得输入构造样本。未知标为证据不足。
4. **外部攻击链评测候选**：[MITRE Wizard Spider Timeline Reconstruction](https://huggingface.co/datasets/the-mitre-corporation/wizard-spider-cyberattack-timeline-reconstruction)，一套受控仿真、36 个分析师审阅活动和 313 条证据观察。作为额外封存案例；日志解析、与系统模式映射、评分器和来源重合审计都还要实施，不把它当现有系统已跑通的标准基准。
5. **比较方法**：同一封存集评估现有 4B、原始 8B、8B SFT/QLoRA，分别报告每类召回和精度、正常误报、JSON 合法率、证据引用准确率、证据不足处理、延迟；增加仅规则和完整链路对照。拆出与模型无关的程序关联能力，避免将所有结果归功于模型。

初次正式混合可把总规模控制在约 1 万条经筛选样本作为试验预算，分配覆盖 Web、系统日志、证据关联、中文报告及困难反例；这是目标预算而非已构造数量。按验证集表现调整采样和训练轮数，训练集质量与分组独立性比照搬大量模板更重要。
