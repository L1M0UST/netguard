**安全日志垂域模型 LoRA＋SFT 与评测最终方案**

调研截至：2026-11-14。适用代码：`E:/platform_taishi/taishi_platform`。本方案完成了代码检查、公开来源检索、元数据与部分实际文件核验；尚未构建最终 SFT 集、训练新模型或执行新一轮模型评测。

**1．选定的路线**

首轮使用 **Qwen3-8B＋4bit QLoRA**，分三轮 SFT：先补多类型日志研判，再补事件证据关联与报告，最后用训练池中的困难样本修正误报、遗漏和证据不足时的过度判断。三轮继续训练同一个 8B 适配器，并在后两轮回放前序数据。4B 适配器不迁移到 8B。

正式训练来源选定为：**清洗后的比赛数据、2026 HTTP 多类数据、AIT-LDS v2.1、AIT-ADS v1、Splunk Attack Data 的主机日志，以及仅取自这些训练分区的任务样本**。不把公开 benchmark 的问答或标准报告加入 SFT。

最终采用分项评测：**Web 分类及对抗请求、多源日志与告警降噪、Windows 跨来源日志、证据与运营任务、生产日志案例、CyberSOCEval 官方外部参考**。比赛 11000 行作为兼容性回归；其已有训练历史使其不适合承担“未见数据泛化”的证明。

27B、DPO／RL 和完整调查 Agent 不进入第一轮必做范围。先确认 8B 在上述任务中的收益，再决定是否增加训练规模和系统能力。

**2．代码决定模型应当学什么**

| 代码事实 | 对训练与部署的影响 |
|---|---|
| `llm/cqsec.py:26,92` 的研判指令与输入仍是七字段 HTTP 告警，输出靠四段文本和正则提取 | 新模型需要版本化输入和结构化答案；单换权重不能完整支持认证、审计和主机进程日志 |
| `m1/run.py:1062` 的本地级联使用 `message` 作为请求体的备选输入 | 非 Web 消息可被传入，但其账号、事件编号、进程关系没有专门的模型输入契约 |
| `m1/run.py:684` 的标准字段较通用，缺少专用进程／账号扩展；缺失协议默认 HTTP | 增加 `log_type`、来源及可选扩展字段，未知字段保留为空，不补造 HTTP 语义 |
| `m1/run.py:999,1024` 的语义研判受候选数及比例限制，默认最多 24 个候选、比例不超过 1% | 万级吞吐不能解释为大模型逐条分析万条日志；需分别测模型能力、候选覆盖和全流程表现 |
| 本地置信度主要由风险文本和代码规则映射，见 `m1/run.py:1112` | 当前值不是校准过的正确概率；训练答案不灌入固定 0.95 等任意置信度 |
| M2 已有 `FineTunedModelProvider`，使用标准 system/user 消息和 OpenAI 兼容接口 | 复用 `LLM_PROVIDER=finetuned` 等配置接入新服务，无须重做 provider 框架 |
| M2 的 `LLMAttackAnalysis` 已包含阶段、实体、`evidence_event_ids` 和 `uncertainties` | 第二轮直接对齐现有结构，复用证据校验；严重度仍由确定性评分决定 |
| M2 的 prompt builder 有事件与证据长度限制 | 扩充上下文前先补证据选择，不能把训练时完整证据、运行时截断证据混为同一任务 |
| M3 当前已调用本地知识问答，driver 已调用运营总结；统计问题可由程序直接回答 | 优先训练“读给定事实、引用证据、解释与总结”，不让模型负责精确取数与计数 |
| `event_report`、`attacker_profile` 客户端存在，但本轮代码搜索未发现同等明确的主流程直接调用 | 报告和画像纳入模型能力验证，单独列出后续接入项，不声称已经完成生产调用 |

本轮读取的主训练集 v3.1 共 15916 条：分类 14296，报告 108，画像 434，问答 720，运营总结 358。分类占 89.82%。原报告构建包含已有类别和模板答案，所以其数量及低训练损失不等同于独立的事件发现能力。代码和来源版本的快照见 `revision_snapshot.json`。

最新 `docs/evidence/ml_acceptance_20261114.json` 记录的运行模式是 `local_m1_and_deterministic_m2`，当次本地大模型不可用。它可以证明当时的确定性管线表现，不能作为新旧 LoRA 的比较结果。仓库当前已有 ML 检测代码，本方案评测期间应固定其工件和配置，避免把 ML 收益归到大模型上。

**4．数据划分在生成指令与答案之前完成**

AIT 使用以下固定分区，原始日志、派生告警、同场景报告和问答全部绑定同一分区：

| 分区 | 场景 |
|---|---|
| train | fox、harrison、russellmitchell、santos |
| dev | shaw、wardbeck |
| sealed test | wheeler、wilson |

这些场景来自同一测试床系列，存在相近攻击流程，所以这是场景泛化测试，不宣称覆盖全部未知攻击。Windows 跨来源与生产日志案例用于补足这一限制。

D1 的 baseline 以载荷族分组，目标比例 80/10/10。先建立跨文件指纹和近似族，再采用 **sealed test 优先于 dev、dev 优先于 train** 的归属规则；测试与开发文件的原始条目保留，碰到同族时从训练池剔除。处理方式、被移除数量和实际比例全部入账，不能靠改动测试集维持理想配比。

指纹至少包含原始字段哈希、受控解码后的内容哈希、词元／结构近似指纹。保留原文与解码视图，不能将所有特殊字符抹平而误合并攻击语义。旧数据的增强副本、翻译、同源报告和同事件窗口也必须继承 group_id。IP／主机去标识按场景做一致映射，保留关联关系，不让固定攻击 IP 成为分类捷径。

D4 按采集场景／运行实例划分 70/15/15，并记录模板族。D4 中引用、搬运或高度近似 OTRF 测试源的材料从训练剔除；使用样本实际哈希及来源元数据核对。若不能可靠区分某组谱系，该组整体进入测试保留区，不作为独立的跨来源训练材料。

任何公开 benchmark 的答案、标准分析报告、检测真值及测试场景标签都不能进入训练、知识检索索引或教师提示。任务运行时提供原始测试日志作为待分析证据是允许的；把测试解答作为知识提供给模型则不是同一件事。

**5．统一训练样本，分别对齐实际接口**

采用一个多任务适配器、带任务标识的消息样本。固定官方聊天模板，关闭思考模式作为首轮配置；训练与推理的角色、模板及任务标识保持一致。新 8B 使用版本化消息协议；旧 4B 的单 user 协议保留在旧适配路径，不能全局修改后再声称旧模型没有退化。

输入包含 `task_type`、`schema_version`、`log_type`、来源类型、事件列表、程序统计、可选资产背景和检索证据。事件保留 `event_id`、时间、主体、行为及 source-specific 扩展：HTTP、认证、进程、Windows 事件、设备告警各有可选字段。缺失值为空，不替 HTTP 数据补状态码，不替主机数据补 GET 和根路径。

| 任务 | 训练目标 |
|---|---|
| m1_judge_v2 | verdict、attack_family、可选 competition_label、attack_outcome、简短 evidence、missing_evidence |
| m2_candidate_v1 | 现有 LLMAttackAnalysis：candidate_id、verdict、stages、threat_entities、evidence_event_ids、uncertainties；风险提示只作建议 |
| evidence_qa_v2 | 从给定证据回答，返回引用与无法确认的内容；上下文未提供的事实不补造 |
| report/profile_v2 | 基于已给证据组织时间线与画像，区分事实和推断，不因出现请求载荷就写“主机已失陷” |
| ops_summary_v2 | 读取程序计算的统计，解释风险与优先级，数值不可改写 |

M1 的 malicious 与 M2 的 attack 按接口适配，不能把不同枚举直接混用。新增主机类别通过 attack_family 承载；保留原比赛标签投影，避免强行把凭据窃取、提权等塞进八类 Web 标签。

`attack_outcome` 独立表示 succeeded／blocked／failed／unknown。WAF 拦截的恶意请求仍可属于攻击尝试；阻断不是正常访问，存在攻击尝试也不等于成功。CMDi 不自动证明 RCE 成功，LFI 与目录遍历也不能无条件一一替换。ATT&CK 通过证据和冻结知识版本判断，不继续把每个 Web 类别固定映射到一个技术。

答案只要求可核对的短依据，不采集不可验证的长篇思维链。置信度如需对外输出，使用开发集校准的服务侧分数；无法获取可靠概率时报告分桶表现与覆盖率，不把模型自报数字称为真实概率。

**6．三轮 SFT 的执行配置**

| 轮次 | 有效新样本目标，不含回放 | 数据与能力 | 初始配置 |
|---|---:|---|---|
| A：日志判别 | 20000～26000 | D0/D1 训练分区＋部分 D2/D4 短窗口；Web 与主机基本行为、正常／恶意／可疑／证据不足、结构化输出 | 2048 token；1～2 epoch；LR 1e-4 |
| B：证据关联与业务任务 | 8000～12000 | D2/D3/D4 的训练事件；M2 JSON、证据问答、报告、画像和运营总结；至少覆盖双源佐证、反证与缺失证据 | 4096 token；1～2 epoch；LR 5e-5；约 30% A 轮回放 |
| C：困难样本修正 | 2000～4000 | 仅从训练诊断池挖掘：正常运维、缺字段、失败／阻断、近似载荷、多重编码、提示注入、上下文无结果等 | 2048/4096 token；约 1 epoch；LR 2e-5；约 40% 前轮回放 |

以上数量是构建预算，不是已产出的样本数；不足的独立场景不以大量改 IP 副本凑数。B 轮将关联、证据问答和报告分开记录，目标至少 1000 条事件分析、1000 条证据问答、500 条运营总结；其余按真实日志来源分布分配。生产中的正常比例与训练采样比例分开保留，评测降噪不使用人为平衡后的流量替代自然分布。

共同配置：bitsandbytes 4bit NF4、double quant、BF16 计算，LoRA rank=16、alpha=32、dropout=0.05，目标为注意力和 MLP 投影；batch=1、梯度累积=16、gradient checkpointing、warmup≈0.05、梯度裁剪 1.0。先验证 r16，不同时把 r32、长上下文和大批量一起打开。每轮学习率与 epoch 由开发集决定，不以训练损失最低作为唯一选择。

先完成 200～500 条协议与标签试验，再用稳定的 20～50 个优化步骤测显存、有效 token/s 和步骤时间。4090 24GB 为首选；48GB 更适合较长证据窗口和并行，但训练速度还取决于具体卡型。三轮继续同一适配器，保留 A/B/C 独立 checkpoint；如果切换 rank 等结构，另建清楚的实验，不冒充连续训练。

教师生成的样本必须有 provenance、真值来源、原始事件和校验记录。全部自动检查 JSON、事件 ID、数值、枚举与真值矛盾；高风险“成功入侵／凭据泄露”等结论逐条核查；其余按来源、类别和模型分歧分层抽查。统计及 ATT&CK 候选由程序／知识资料提供，教师不能创造数据真值。

第三轮不回灌最终测试错误。开发集用于选择方向和 checkpoint，原文不加入训练；困难样本从训练池中挖掘同类问题。多轮指分阶段训练，不要求本次实现一个多 Agent 调查平台。

B1～B5 合称“平台日志与证据评测 v1”，属于公开来源与本项目协议组成的测试套件。每个部分各自报告来源和标注质量，不称其为某个论文的官方 leaderboard。B5 的 100 例完成复核前，只能报原始规则标签代理指标，不能提前声称获得人工真值。

E1 固定 PurpleLlama commit `0654501399e7cbd560db9501965dc09c567a5563` 与 CrowdStrike 数据 commit `ce7daa5bc7da51559ca97476d2277be02631783e`。小上下文采用官方支持的 `--truncate-input` 模式，并单独标注。该模式会过滤／截断报告字段，仍需实际统计输入 token；超长、超时及解析失败保留在总分母中，不能静默跳过。这里的官方选项是可复现评测配置，不是任意截断后仍声称与未截断结果相同。

辅助参考选 [CyberSOCEval TIR text](https://github.com/meta-llama/PurpleLlama/blob/main/CybersecurityBenchmarks/website/docs/benchmarks/threat_intelligence_reasoning.md) 的 588 题；它测威胁报告理解，用 text 模式匹配纯文本 8B。CTI-MCQ 与 CyberMetric-500 留作知识与遗忘检查，不充当主日志成绩。全部辅助 benchmark 不进 SFT。

**8．把 2025—2026 论文转成可执行改进**

| 论文及状态 | 已核对的相关发现 | 本系统采用的改进 |
|---|---|---|
| [Fine-Tuning Large Language Models for Security Log Data Labeling，2025，JKSCI 正式论文](https://doi.org/10.9708/jksci.2025.30.10.143) | 研究代表性与不确定性结合的样本选择，使用其特定日志与 GPT-4o mini；不是证明任意开源模型只需数百条 | C 轮按来源覆盖、类别与模型分歧挖困难样本，先审标签，避免只追求行数 |
| [ExCyTIn-Bench，2025；作者仓库标注 ICML 2026 接收](https://arxiv.org/abs/2507.14201) | 用调查图中的节点与路径构造有证据链的安全问题 | B 轮根据训练事件图构建多跳问答，引用真实事件；模型不生成不存在的证据边 |
| [CyberSOCEval，2025，预印本](https://arxiv.org/abs/2509.20166) | 更大模型与更现代模型总体较强，但额外思考没有稳定复现数学／代码领域的收益 | 首轮关闭长思考，以正确证据、短答案与时延为目标；是否开启思考由同题同预算实验决定 |
| [Retrieval-Augmented LLMs for Security Incident Analysis，2026，作者标注 CAIS 2026，v3](https://arxiv.org/abs/2603.18196) | 查询筛选＋异构日志检索支持事件分析；跨片段整合仍有明显模型差异 | 按实体与时间检索、保留双源佐证和反证；训练模型整合多个证据片段，而不是只扩大 token 窗口 |
| [From Investigation Failures to Reliable SOC Agents，2026-10，预印本](https://arxiv.org/abs/2610.10608) | 空检索被误当成关闭依据，同上下文反思可能放大错误；其 Alert-Bench 派生自 AIT | 加入“无结果不等于正常”、缺失遥测和独立反证检查；不将同一模型重复回答视为独立证据，也不把其 AIT 衍生测试算新独立来源 |
| [REFINE，2026-09，预印本](https://arxiv.org/abs/2609.32516) | 将分析师反馈和召回约束结合；其后续测试并非所有场景都保持 100% 召回 | 先约束误关闭与关键攻击召回，再优化降噪；反馈经确认进入下一版本训练，不直接在线自改规则 |
| [When the Ruler is Broken，2026-05，预印本](https://arxiv.org/abs/2605.07293) | 小规模案例显示自由文本正则解析会明显改变测得成绩 | 冻结 scorer；报告语义正确与格式合格两项；新模型优先 JSON 约束，旧模型用固定适配器，保留原始输出 |
| [APTInvestBench，2026-09，预印本](https://arxiv.org/abs/2609.38954) | 区分日志中存在、被检索获得、被最终引用的证据支撑 | 分别测证据可用率、检索覆盖和引用保留，设计缺主机／缺网络／缺请求体的遥测消融 |

这是根据论文作出的工程选择，不是声称其已在本平台产生同样收益。OpenSOC-AI 等极小样本演示不作为本项目准确率承诺或数据规模依据。旧日志异常论文与系统故障 benchmark 也不直接替代安全攻击评测。

不进入首轮：自动修改检测规则、任意 SQL／Shell Agent、大规模 RL、把最新 IOC 和全部 CVE 记进权重。新鲜知识通过带版本的 ATT&CK／情报检索提供，SFT 学的是证据使用、任务协议与边界。

**9．必要的代码配套及边界**

1. 在原始日志解析和标准化侧增加来源适配：syslog、认证、审计、Windows 与设备告警保留必要扩展字段和原文引用；解析、分窗、统计由程序完成。
2. 为本地客户端增加 v2 协议，支持 typed evidence、任务标识和结构化答案。保留旧 4B 路径；训练协议切换不是把旧注释删掉即可完成。
3. 为 M1 输出做八类兼容投影，并保留主机 attack_family、unknown 与 outcome。更新涉及的标签白名单和 bridge，防止新标签被过滤为空或强制落到待研判。
4. M2 直接复用 finetuned provider 与现有证据校验。先影子运行对比，再选择替换范围；不改变确定性风险分数的最终权责。
5. M3 用检索后的事件与程序统计回答，返回可核对引用；报告与画像补齐真正的调用和状态记录后，才认定已经接入。
6. 模型、适配器、提示词、数据分区、知识库、量化文件、ML 工件均有版本与哈希。切换模型时隔离现有研判缓存，不能复用 4B 旧答案制造 8B 高速结果。

代码改动是后续实施项，本轮只产出调研方案与清单，不修改业务逻辑或启动服务。

**10．比较实验、指标与上线判定**

固定四个核心比较条件：当前 4B、原始 Qwen3-8B、新 8B SFT、SFT＋证据检索；再比较新模型 BF16 与部署量化版。A/B/C checkpoint 在开发集比较；在打开封存测试前预先确定最终模型和待报告消融条件，最终测试不参与选择下一轮训练样本。

| 检查项 | 首轮拟定验收目标，均非已达成绩 |
|---|---|
| 多源日志效果 | 主测试集 macro-F1 相比原始 8B 争取增加至少 3 个百分点；按来源与类别报告，不靠知识题平均分替代 |
| 正常误报与攻击保留 | 开发集按目标 FPR≤1% 选择阈值；最终报告实际 FPR、召回和不确定区间，不承诺分布外仍满足同一阈值 |
| 关键 Web 类 | RCE/CMDi 等单列召回，要求说明误报代价；不把 CMDi 请求识别计为主机成功入侵识别 |
| 结构与引用 | JSON 合格率目标≥99%；引用 ID 存在性要求 100%；语义支撑另行人工判定 |
| 报告与总结 | 程序事实数字一致性要求 100%；200 案例中不接受无证据的“成功失陷／数据已泄露”等关键断言 |
| 量化 | macro-F1 相比 BF16 的降幅目标≤1 个百分点；关键类单列，不能用平均分掩盖 |
| 部署 | 测 p50/p95 时延、超时、峰值显存、吞吐、缓存命中、降级和失败原因；不预填性能结论 |

同时报告 unknown／review 比例和覆盖率，避免模型全部输出“未知”获得低误报，也避免把所有未知当正常。类型分类单独评分；安全降噪中把恶意事件关闭为 benign 作为关键漏报，review／unknown 不算成功自动关闭。对每个来源保存全分母、超时与格式失败；以事件／窗口为比较单位，报告样本及场景数。重复衍生问题不能当独立样本扩充置信度。

模型对照使用相同可见证据和任务语义、各模型正确的官方聊天模板及明确 token 预算。旧 4B 用冻结的旧协议适配器，另报其格式问题；否则“新模型改 JSON”可能被误读成全部语义能力提升。

端到端再做两组：固定规则／ML、关闭云端独立复核以隔离本地模型增益；以及正常生产 hybrid 模式测全链表现。两组均记录真实 provider、model、模型调用数、候选选择、裁剪和 fallback。模型单独直测覆盖全部测试样本，不能受 M1 top-24 门控影响；生产流程则明确报告哪些事件实际进入了模型。

对降低告警量的目标，分别报告精确去重、事件合并、模型建议关闭三种减少。第一版不因模型一句 benign 直接清除强规则或 IOC 信号。新模型未达到质量目标时保留旧版本，失败也形成可复查的比较报告。

**11．算力、产物和实施顺序**

Qwen3-8B 固定 HF revision `b968826d9c46dd6066d109eabc6255188de91218`，约 8.19B 参数，模型卡为 Apache-2.0。[官方模型](https://huggingface.co/Qwen/Qwen3-8B)。首选单张 4090 24GB 完成 QLoRA；长序列先做实测，不把优化框架的最低显存表当实际峰值保证。

训练耗时按各轮实际 token 数、稳定步骤时间和有效 token/s 测算；前文针对旧 1.59 万短样本的小时估算不直接套用。数据清洗、教师生成、专家核验、训练、导出、评测分项记录。系统内存 90GB 不能直接抵换显存；数据规模也不要求一次加载到 GPU。

先在云端部署 8B OpenAI 兼容服务完成基准，再验证本机 4060 8GB 的 Q4 版本。当前 8192 总上下文／4 槽约为每槽 2048，不能因此声称每请求已有 8K。长证据评测使用单并发及单独上下文配置；模型大小、KV cache 与输出预算一起核对。若本机时延或显存不达标，保留本地 4B 快路径，8B 承担云端或专用研判服务。

实施顺序固定如下：

1. 冻结数据谱系、测试分区和 scorer；补必要日志字段与 v2 协议。
2. 完成来源导入、去重、标签审查及 200～500 条小样本试验；先测原始 8B。
3. 构建 A 轮，完成一次有效 SFT；开发集验证，确认不是模板／解析或标签问题。
4. 构建 B 轮，验证跨源证据、报告、问答与数字一致性；复用 M2 provider 做影子运行。
5. 仅使用训练诊断池完成 C 轮；固定最终 checkpoint、阈值、RAG 和量化配置。
6. 一次性执行预注册的最终比较条件与 B0～B5、E1；辅助知识和可选调查型实验分表。
7. 根据真实质量与部署数据决定切换，保存模型卡、数据卡和失效案例。

后续应交付的执行产物：分区 manifest、清洗／近重复报告、带来源的 SFT JSONL、A/B/C 训练配置及日志、适配器与基座版本、部署工件、原始预测、官方与自建 scorer 版本、逐来源指标、人工复核记录和端到端运行状态。
