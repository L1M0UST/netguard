# 模型训练创新指南（修订版：含实测耗时 · 选型 · 超参 · 数据 · 云上部署）

> 2026-09-21 修订。基于全网调研（LLaMA-Factory 官方文档、Qwen 官方训练文档、vllm-ascend、
> TextReasoningBench/SIABENCH 论文、TRAM/SecGPT 数据集、九天 Gitee/ModelScope 实测检索）+
> 本平台两轮全量实测。出处链接随文标注。

## 一、问题1：全链路实测耗时与压缩方案（已实测）

### 1.1 两轮 1.1 万条全量实测（智能模式）

| 阶段 | 首跑（冷） | 复跑 | 构成分析 |
|---|---|---|---|
| M1 解析+降噪+级联 | 3m20s | 2m45s | 规则底座仅 10-20s；**L3 级联 110 次本地 cqsec 调用占 ~2.5-3min**（并发3） |
| bridge 契约转换 | ~1s | ~1s | 6575 事件展开+标签 |
| M2 关联+研判 | ~5m | ~3m50s | 规则关联 40-60s + **Top-60 flash 调用 ~3-4min**（并发5） |
| 运营总结(cqsec)+bundle 写盘 | ~30s | ~25s | 6577 链校验+写盘 |
| **端到端** | **8m22s** | **6m36s** | 级联判决 110/110 全本地、0 次云端（两轮一致） |

参照系：极速模式（纯规则+本地，0 云调用）实测 **2m28s**；380 行样本端到端 **~30s**；
M1 单机吞吐基准：10 万行 CSV 10.5s；M2 关联 ~2500 events/s。

### 1.2 压缩方案（预期 4-5 分钟）

| 手段 | 改动点 | 预期收益 |
|---|---|---|
| M1 级联并发 3→4 | `workspace/m1/config.json` llm.max_concurrency（cqsec 服务恰 4 槽） | L3 段 -25% |
| 级联第一档换 JSON 短输出 | 训练"级联研判头"（§3 方向A）替代四段式，输出 token 减 60% | L3 段 -30~50% |
| M2 并发 5→8 | `config.yaml` llm.max_concurrency | M2 LLM 段 -35% |
| M2 预算 60→40 | `config.yaml` llm.max_candidates | M2 LLM 段 -33%（ Top-N 按风险分，覆盖面损失小） |
| 演示兜底 | 380 样本（30s）/ 极速模式（2m28s） | 保底不翻车 |
| 物理下限认知 | 规则底座 ~2 分钟与 LLM 时间线性于预算，压不动 | — |

## 二、问题2：训练还是微调？底座怎么选（九天 Chat V3 / Qwen3-8B / DS-R1）

**结论：微调（SFT + LoRA），不从零预训练。** 从零训练一个安全垂域模型需要千亿 token 级语料，
比赛周期内不现实也没必要——QLoRA/LoRA 在 1-2 万条高质量指令数据上就能把 4B-8B 底座调到任务可用，
我们 4B 版本 16 类分类 macro-F1 97.05% 就是证明。

### 2.1 候选底座核查结果（2026-09 实查）

| 候选 | 核查结论 | 出处 |
|---|---|---|
| 九天 Chat V3 | **开源的只有 JIUTIAN-139MoE-Chat**（总参 38.8B/激活 13B MoE，Apache-2.0+商用审核）——远超比赛资源；Gitee 官方组织另有 JT-Math-8B（数学）/JT-DA-8B（结构化数据）等垂直模型，**无通用 dense Chat 小规格**；未上架 HuggingFace。官方"震泽 MaaS 平台"提供 OpenAI 兼容 API 与微调服务 | gitee.com/CMCC-jiutian/JIUTIAN-139MoE；blog.csdn.net/yzx991013/article/details/149001573 |
| Qwen3-8B | LLaMA-Factory 官方 910B Docker 镜像 `hiyouga/llamafactory:latest-910b-ubuntu`，Atlas A2(=910B) 官方支持 SFT/LoRA/合并，融合算子覆盖 Qwen3 系列；官方示例 `examples/train_lora/qwen3_lota_sft.yaml`（rank 8/lora_target all/template qwen3_nothink/cutoff 2048）。注意：Qwen3 官方训练文档标注 "To be updated for Qwen3"，超参以官方示例+自查微调为准 | github.com/QwenLM/Qwen3/blob/main/docs/source/training/llama_factory.md；llamafactory.readthedocs.io/zh-cn/latest/multibackend/npu/npu_training.html |
| DS-R1 蒸馏系 | **不推荐用于我们的任务**：R1-Distill-Qwen-7B 底座是 Qwen2.5-**Math**-7B（数学特化）；"8B"实为 Llama-3.1-8B 底座。TextReasoningBench（arXiv:2603.19558）实测：长思维链对分类任务 token 膨胀 10-100× 只换 +1~3%，小模型上甚至有害 | huggingface.co/deepseek-ai/DeepSeek-R1-Distill-Qwen-7B；arxiv.org/abs/2603.19558 |

### 2.2 推荐

- **主路线：Qwen3-8B 微调**（910B 云训练 + vllm-ascend 云部署，见 §5），现有 **Qwen3-4B 本机版继续当级联第一档**（97% F1 已近饱和，4B→8B 的分类增量建议先在"困难类/长文本"上验证再切换，未查到公认基准）。
- **九天**：不作微调底座；在报告/问答里以**震泽 MaaS API 挂载**展示国产化适配（我们 llm 客户端全是 OpenAI 兼容，加一个 provider 配置即可）。
- **R1 蒸馏**：不选。若 M2 某些候选确实需要推理，用 Qwen3-8B 的 **think 模式开关**（可控）或直接 DeepSeek-flash。

## 三、问题3：哪些地方用模型？用模点 × 模型对应矩阵

| 用模点 | 任务性质 | 推荐模型 | 理由 | 备选 |
|---|---|---|---|---|
| ① L3 级联第一档（单告警研判/16类分类） | 高频、短文本、需**可解析置信度** | **Qwen3-4B 级联研判头**（现有模型微调出 JSON 输出版，§4 方向A） | 已 97% F1；级联实测 110/110 全本地接住、0 云调用；SIABENCH 佐证"初筛用小模型"范式（arxiv 2603.06422） | 8B 验证有增益后切换 |
| ② M2 攻击链候选研判（Top-N） | 低频、长上下文、需推理+JSON 服从 | **DeepSeek-flash（现状）** | 推理质量/成本已验证；R1 不适用（§2.1） | 910B 部署 Qwen3-8B think 模式 |
| ③ 智能问答（知识类）+ 运营总结 + 事件报告/画像 | 生成类、中文、四段式 | **Qwen3-8B SFT（五能力加强版）@ 910B** | 8B 在生成/总结上收益大于分类；云部署吞吐支撑并发问答 | 现有 4B 本机；九天 API（加分项） |
| ④（可选）证据检索向量化 | RAG 检索 | 未纳入本轮核验，需另测 BGE 系嵌入模型 | — | — |

一句话：**小模型管"多与快"（分类/初筛/级联），大模型管"深与准"（推理/生成），云端管兜底**——这正是
TextReasoningBench/SIABENCH 支持的分档范式，也是我们答辩的"成本-准确率帕累托"故事。

## 四、问题4：超参怎么选、微调数据从哪来

### 4.1 超参（按验证顺序给，不拍脑袋）

**本机 RTX 4060 8GB（4B，已验证可跑）**——沿用现配置：
```yaml
quantization_bit: 4        # QLoRA（8GB 必需）
lora_rank: 16; lora_alpha: 32; lora_target: all
cutoff_len: 768; per_device_batch 2 + grad_accum 8; lr 1e-4; epochs 3
template: qwen3_nothink    # 与推理端一致，禁思考模式
```

**910B 云（8B，推荐起点）**——注意 **NPU 上 QLoRA 非一等公民**（bitsandbytes 需分支编译+关 double
quantization），**用纯 LoRA bf16 最稳**（64G 显存完全放得下）：
```yaml
# 基于 LLaMA-Factory 官方 qwen3_lora_sft.yaml 修改
model: Qwen3-8B；quantization_bit: null；bf16: true
lora_rank: 16~32（任务简单取16，先16验证）
lora_target: all；cutoff_len: 2048（比本机翻倍，长告警/事件报告受益）
lr: 5e-5 起步（LoRA 常用区间 5e-5~1e-4；比官方全参 5e-6 高一个量级）
epochs: 2~3 + 按验证集 F1 早停；per_device_batch 8（910B 显存富余）
```
调参顺序（低成本→高成本）：先 1 个 epoch 短跑看 loss/格式服从 → 调 lr（欠拟合×2，过拟合/10）→
再满 epochs → 最后才动 rank。**每次只动一个**。分类任务看 macro-F1/混淆矩阵（复用 `03_eval_f1.py`），
不看 loss。

### 4.2 数据从哪来（三层）

**第一层：数据飞轮（核心资产，零标注成本）**——平台每次运行都产语料：
```
M1 semantic_judgements.parquet（证据+verdict+置信度）  → 能力①研判 SFT 对
M2 chains.json（阶段/证据/评级/narrative）             → 能力②事件报告 SFT 对
attackers.json + 行为摘要                              → 能力③画像 SFT 对
bundle metrics + 报告                                  → 能力⑤运营总结 SFT 对
官方 1.1万条 + 规则命中标签（已验证 F1 97%）            → 分类骨干
```
抽取脚本复用大赛项目 `model/data/01~07_*.py` 的 alpaca 格式（instruction=能力指令，
input=字段行，output=目标文本）。**方向 A（级联研判头）**：output 改为
`{"label":"...","confidence":0.xx,"risk":"高|中|低"}` 单行 JSON，3000-5000 条即可。

**第二层：公开数据集增广（核验过的）**：
- **TRAM**（MITRE CTID）：CTI 报告→ATT&CK 映射标注，Apache-2.0——增强"技术映射"能力
  （github.com/center-for-threat-informed-defense/tram）
- **SecGPT V2.0**：5TB 安全语料（法规/漏洞/CTF/日志），可抽 SFT 子集
  （github.com/Clouditera/secgpt）
- **CIC-IDS2017** / **CTU-13**：流量域标注数据——与告警文本有域差，仅作预训练增广
  （unb.ca/cic/datasets/ids-2017.html；stratosphereips.org/datasets-ctu13）
- 中文告警研判专用公开语料：未查到可靠版本——**自有数据就是护城河**（答辩点）

**第三层：构造规范（质量>数量）**：
- 每能力 1-3k 条即可显著改善；类均衡（16 类各 ≥150）；困难负例（正常访问含敏感词、混淆编码载荷）
- 注入样本必含（配合⑥：正常语义+注入片段的混合样本，训练模型识别并拒绝）
- 全局去重（内容指纹）、验证集 10% 不参与训练、格式严格对齐 `qwen3_nothink` 单条 user 消息
- 评测集固定冻结（官方 1.1 万条 holdout + 每版本跑同一份回归，版本可比）

## 五、微调完直接云上部署（910B）

**方案：vllm-ascend**（vllm 官方昇腾插件，Apache-2.0；stable v0.23.0，锁定 CANN 9.1.0 /
PyTorch 2.10 / torch_npu 2.10.post4；910B 属 Atlas A2 系列）：
1. 焕新平台选含 CANN 9.1 的镜像 → `pip install vllm-ascend`（或官方 docker）；
2. 权重放对象存储 → 起服务：`vllm serve /path/to/merged-qwen3-8b --port 8000`（自带 OpenAI 兼容 /v1/chat/completions）；
3. 平台零代码接入：`.env` 把 `CQSEC_BASE_URL` 或 `FINETUNED_API_BASE_URL` 指向云地址（llm/cqsec.py 与
   M2 finetuned provider 都是 OpenAI 兼容）；公网暴露记得自定义 UA/网关鉴权（Cloudflare 教训）；
4. 回归：跑 `orchestrator.driver run-file --file sample_alerts.csv` 全链对比 baseline。
MindIE（华为官方推理引擎）为备选（支持矩阵本次未能核验）；llama.cpp 无昇腾后端。
本机 GGUF 链路保持不变——**云端挂了自动回本机**（llm/cqsec 客户端已支持双地址切换）。
